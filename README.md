📌 Project Overview

This project focuses on Footprinting, Open Source Intelligence (OSINT), Reconnaissance, and Network Scanning as part of Week 2 of my Cybersecurity Internship at Networkwalks.

The purpose of these practical assignments was to understand how penetration testers collect information about a target, investigate publicly available data, identify relationships between digital assets, and discover active devices within a network.

Throughout this week, I completed five practical modules using different cybersecurity tools and techniques.
📚 Internship Learning Progress

As part of my Week 2 cybersecurity training, I completed the following five Project Modules:
🔎 W2-PM1 – Footprinting with Multiple Kali Linux Tools

Performed domain reconnaissance using several Kali Linux tools to collect publicly available information about a target website and its infrastructure.

Activities included:

    WHOIS domain information gathering.

    Website technology fingerprinting with WhatWeb.

    DNS lookups using Nslookup.

    HTTP response header inspection using cURL.

    Web Application Firewall detection using Wafw00f.

    DNS enumeration using DNSRecon.

🌐 W2-PM2 – Footprinting with Google Hacking Database (GHDB)

Explored Google Hacking Database and practiced advanced search operators to identify publicly indexed information.

Activities included:

    Exploring the Google Hacking Database.

    Practicing Google Dorks.

    Searching for publicly indexed resources.

    Understanding potential information exposure through search engines.

    Learning how search operators support reconnaissance activities.

🕸️ W2-PM3 – Footprinting with Maltego

Used Maltego to investigate and visualize relationships between digital entities.

Activities included:

    Performing OSINT investigations.

    Exploring domain and IP-related information.

    Using Maltego transforms.

    Identifying relationships between digital entities.

    Creating graphical representations of collected information.

📧 W2-PM4 – Footprinting with theHarvester

Used theHarvester to collect publicly available information associated with a target domain.

Activities included:

    Gathering publicly available email addresses.

    Discovering subdomains and hostnames.

    Identifying associated domains.

    Exploring automated OSINT information gathering.

    Understanding the importance of publicly exposed information.

🖥️ W2-PM5 – Network Scanning with Zenmap

Performed network discovery on my own local LAN using Zenmap, the graphical interface for Nmap.

Activities included:

    Identifying local IP address and subnet configuration.

    Discovering active hosts using Ping Scan.

    Identifying IP and MAC addresses.

    Reviewing network discovery results.

    Generating a network topology.

    Exporting the network topology as a PDF document.

🪜 Practical Modules & Activities

🔎 Module 1 – W2-PM1: Footprinting with Multiple Kali Linux Tools

The first module focused on collecting publicly available information about the target domain using multiple Kali Linux tools.
Tools Used

    WHOIS

    WhatWeb

    Nslookup

    cURL

    Wafw00f

    DNSRecon

Activities Performed

1. WHOIS – Domain Information Gathering

Collected publicly available domain registration information and identified domain-related details, including name servers.

2. WhatWeb – Website Fingerprinting

Identified website technologies, CMS platforms, plugins, and other technical information.

3. Nslookup – DNS Resolution

Performed DNS lookups to identify the IP address associated with the target domain.

4. cURL – HTTP Header Inspection

Used the -I option to inspect HTTP response headers returned by the website.

5. Wafw00f – WAF Detection

Checked whether a Web Application Firewall was present and identified the technology reported by the tool.

6. DNSRecon – DNS Enumeration

Collected DNS-related information, including name servers, mail servers, TXT records, and other DNS records.
Learning Outcome

I learned how different Kali Linux tools can be combined to collect information about a domain, website technologies, and DNS infrastructure.

🌐 Module 2 – W2-PM2: Footprinting with Google Hacking Database (GHDB)

The second module focused on using Google Hacking Database and advanced search operators for reconnaissance.
Activities Performed

    Explored the Google Hacking Database.

    Practiced Google Dorks and advanced search queries.

    Investigated publicly indexed information.

    Learned how search engines can reveal publicly accessible resources.

    Studied potential information exposure through search results.

Learning Outcome

I learned how search engines can be used as an OSINT resource during the reconnaissance phase and why organizations should monitor publicly indexed information.

🕸️ Module 3 – W2-PM3: Footprinting with Maltego

The third module focused on visual reconnaissance using Maltego.
Activities Performed

    Started an OSINT investigation using Maltego.

    Explored digital entities associated with the selected target.

    Used transforms to expand collected information.

    Investigated relationships between domains, IP addresses, and other entities.

    Analyzed the graphical representation of discovered relationships.

Learning Outcome

I learned how Maltego can help visualize connections between digital assets and organize OSINT findings into a graphical representation.

📧 Module 4 – W2-PM4: Footprinting with theHarvester

The fourth module focused on automated OSINT information gathering using theHarvester.
Activities Performed

    Performed information gathering against the selected target.

    Investigated publicly available email addresses.

    Collected domain-related information.

    Identified subdomains and hostnames where available.

    Explored information gathered from supported public sources.

Learning Outcome

I learned how theHarvester can automate parts of the reconnaissance process and help identify publicly available information associated with an organization.

🖥️ Module 5 – W2-PM5: Network Scanning with Zenmap

The fifth module focused on discovering active devices within my own local network.
Activities Performed

1. Identify Local Network Configuration

Used the Windows ipconfig command to identify the local IP address, subnet mask, and default gateway.

2. Configure Zenmap

Entered the appropriate local subnet into Zenmap and selected the Ping Scan option.

3. Discover Live Hosts

Performed network discovery to identify devices responding within the local network.

4. Identify Network Devices

Reviewed the scan results to identify active hosts, IP addresses, and available MAC address information.

5. Generate Network Topology

Used Zenmap's Topology section to visualize the discovered network environment.

6. Export Network Topology

Enabled the topology legend and exported the network topology as a PDF document.
Learning Outcome

I learned how Zenmap can be used to discover active devices, identify network information, and create a visual representation of a local network.
📊 Risk Analysis & Security Observations

The practical activities demonstrated several potential security concerns associated with publicly available information and network visibility.
#	Security Observation	Potential Impact	Risk Level
1	Website technology information exposed	May help identify software requiring security review	Medium
2	Domain registration information available	May reveal infrastructure-related information	Low
3	DNS infrastructure information exposed	May help build an infrastructure profile	Medium
4	HTTP technical information exposed	May assist technology fingerprinting	Low
5	Publicly indexed information	Sensitive resources may be unintentionally exposed	Medium
6	Digital infrastructure relationships identifiable	May help map an organization's digital footprint	Medium
7	Public email addresses and subdomains discoverable	May increase phishing and targeted reconnaissance risks	Medium
8	Multiple live devices discoverable	Unknown devices may be present on the network	Medium

Note: These observations represent potential risks and do not automatically indicate confirmed vulnerabilities. Additional authorized security testing is necessary to validate any actual security weaknesses.
